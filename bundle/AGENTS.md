# Observer installation instructions for agents

Use the root README as the installation contract. First establish actual OS, current client, genuine host execution capability and human installation/metadata-telemetry permission. Install only the clients the user confirmed after detection (README: One-sentence installation). Use the company-site `--authorize` flow; the customer bundle has no private credential importer and no Langfuse login path. If execution tools are absent, report the blocked prerequisite and supply appropriate human-run instructions.

Verify the exact ZIP's supplied checksum and safely extract before running its local OS bootstrap. Use explicit dedicated runtime/config/source/state/bundle paths. Reuse the shared Observer config after the first company-site authorization. Never put keys in arguments, chat, logs, reports, Git or public artifacts. Never invent a key, endpoint, enrollment API, native profile, source event or successful receipt.

After installation inspect only selected health. State separately: registration, source waiting, native event capture, HTTP receipt, and receiver ID readback. An empty initialized WorkBuddy file is waiting state. Native WorkBuddy user hooks must respect effective disable-all/managed-only policy; preserve unrelated settings, hooks, plugins and the ownership receipt. Any unknown ownership or unexpected edits must fail visibly. Tool-less sessions cannot self-install. Never describe Windows, another architecture, or another client as verified without genuine execution evidence.

Native storage is read locally and WorkBuddy may stage a response locally for Skill identity resolution. Preserve private configuration, state, native sources, other selected registrations and shared bundle membership during maintenance. Report native errors; do not add mock content, fabricated success, fallback or hidden failure paths.
